# Nexus Loop — what is real, stubbed, simulated, and what breaks at 100×

This is the one-page note that travels with `loop-report.json`. The report is
produced by `python3 run.py --kit kit --out out/loop-report.json`. The decision
screen is `python3 -m nexus_loop.app --report out/loop-report.json`.

## Real

- Session-grain feature table from `sessions.jsonl.gz` plus one pass over
  `agent_steps.jsonl.gz`. Unknown fields are kept. Required keys are checked.
- Coverage computed from this corpus: a step type is in coverage for a session
  when that session's `agent_kind` emits the step type anywhere. Tool-derived
  metrics therefore exclude `v2_flow` from the denominator rather than counting
  it as zero-error. The value is measured per tenant (practice kit lands near
  0.72 / 0.93).
- Eleven operator asks, each a metric with a number passport (value, fidelity,
  coverage, plan) or a structured gap. A01/A04 measured. A09 `REQUIRES_NEW_JUDGE`.
  A11 `NOT_MEASURABLE` with required event `failover` at step grain, fields
  `from_target, to_target, reason, recovered`, owner `conversation-runtime`.
  `llm_call.retry_count > 0` is named as a proxy and rejected: those are quality
  retries, not failovers.
- A02 is answered twice: a per-intent month-over-month table, and a **mix-adjusted**
  rate that holds month-1 intent shares static and applies month-2 per-intent rates.
  `mix_effect` and `change_beyond_mix` are reported separately, so a traffic-mix
  change is not read as a quality change. Judged quality is never trended across the
  judge-version boundary.
- Cost (A03/A08): coverage is measured (if v2 lacks cost, those sessions leave both
  numerator and denominator; missing cost is `null`, never `$0`). Escalation is
  reported as counts and rates, never priced — no human-handling constant exists.
  An intent that resolves nothing has **unbounded** unit cost: it is ranked first,
  not last.
- Cardinality: a `customer_ref` breakdown is refused against the catalog's
  **fixed budget of 200**. `session_id` is the only join key we use.
- Three detector-specific analyses, no practice tenant/day/intent/tool/agent
  literals: silent tool (empty 200), KB gap with a **same-tenant, same-window,
  same-agent-family** peer baseline (and the nearest `kind=kb` change as the
  candidate, including a born-broken launch), prompt/efficiency with sibling
  agents as the control. Observation and attribution are separate.
- Three explicit non-regressions: traffic mix, load, judge-version boundary.
- Impact uses counts and the sum of recorded `cost_usd`, or null. No invented
  handoff-dollar constant.
- Golden-set session IDs are frozen to `out/golden_set.json` **before** any
  prescription is written and are not recomputed after.
- The screen renders only the report. Approve / reject / defer with a mandatory
  reason updates `prescriptions[].approval` via temp-file + atomic replace,
  re-validates, and appends `out/decisions.log`.

## Stubbed

- No language model is called. Logged facts stay in Python.
- A09 is a gap, not a frustration judge. We did not train or version one.
- Quality calibration is the kit's human rubric labels vs the corpus judge
  (`|Δ| ≤ 1` on the 1–5 scale), published per `judge_version`, never 1.00.

## Simulated

- Replay (`tools/nexus-loop-kit/replay/serve.py`) is a seeded hypothesis
  verifier. Its `before` is not our corpus number. We send at most a few
  high-confidence runs on the exact detected cohort and frozen golden set
  (`tool.validate` first). `no_effect` is recorded as a result. If the URL is
  down, verifications are omitted and the report remains valid.

## Breaks at 100×

- The session map is in memory. ~80k sessions / ~900k steps is comfortable;
  tens of millions of sessions need an on-disk grain.
- The report JSON is the decision store. Atomic replace is fine for one
  operator, not for concurrent approvers.
- Detector bars are relative and statistical, not practice values, but a sealed
  corpus whose empty-success base rate sits under the lift/z floors will not
  fire — that is a miss, not a silent false calm we paper over.

The report is generated by `run.py` from the kit corpus; no hand-edited or
reference report is read or copied.

For the kit's verified behaviour, the catalog-vs-corpus disagreements, the defects
we found in our own pipeline and fixed, and the statistical caveats we state, see
`docs/findings-and-fixes.md`.
